# Калькулятор стяжки пола «Галилео»

Веб-калькулятор для сотрудников компании, которые рассчитывают стоимость работ по устройству стяжки пола и передают расчёт в amoCRM. Рабочая версия приложения, подготовленная к развёртыванию, находится в каталоге `fixed/`.

## Возможности

- Расчёт стоимости по площади, толщине, прайсу и марке стяжки.
- Учёт дополнительных работ и материалов, этажа, расстояния от МКАД, способа оплаты и скидок.
- Формирование подробной формулы расчёта и карточки логиста.
- Подбор адреса и расчёт расстояния через геокодер Яндекса при наличии ключа.
- Сохранение вариантов и логистических примечаний в amoCRM.
- Общие списки водителей, бригадиров, менеджеров и автосмесителей.

## Интерфейс

На странице входа сотрудник вводит общий пароль. После входа открывается форма калькулятора: слева расположены прайс и параметры объекта, в центральных колонках — дополнительные работы и сведения о заказе, справа — итог, скидки и кнопки «Формула» и «Логист». Внизу формы показываются подробности логистического расчёта. Интерфейс собран из HTML-формы, локальных CSS-файлов и JavaScript; отдельный скриншот в репозитории не хранится.

## Требования

| Компонент | Требование | Назначение |

| PHP | 8.0 или новее | Веб-приложение и API |
| PHP cURL | Включённое расширение | Запросы к amoCRM и геокодеру |

| Python | 3.10 или новее | Только пересборка встроенных данных прайса; используются стандартные библиотеки |
| Git | 2.30 или новее | Клонирование и обновление проекта |

Для локального просмотра можно использовать встроенный PHP-сервер. Он предназначен для разработки, а не для публикации в интернете.

## Установка и локальный запуск

Команды ниже приведены для Windows PowerShell. Сначала установите PHP, Git, Node.js и, если планируете пересобирать прайсы, Python. Затем клонируйте репозиторий:

```powershell
git clone https://github.com/svettlanalana6757-web/galileo-floor-screed-calculator.git
Set-Location galileo-floor-screed-calculator
```

Установите PHP-расширение cURL согласно инструкции вашей сборки PHP. Проверьте доступность команд:

```powershell
php --version
php -m
node --version
git --version
```

В выводе `php -m` должно присутствовать `curl`.

Задайте пароль для локального входа и запустите сервер с каталогом приложения в качестве document root:

```powershell
$env:CALC_PASSWORD = Read-Host -Prompt 'Введите локальный пароль калькулятора'
php -S 127.0.0.1:8000 -t .\fixed
```

Откройте `http://127.0.0.1:8000/`. Для остановки сервера нажмите `Ctrl+C` в окне PowerShell. Переменная доступна только текущему окну и запущенным из него процессам. Без `CALC_PASSWORD` приложение намеренно не принимает вход.

В геокодере используется серверный ключ. Если нужно проверить поиск адреса локально, перед запуском сервера задайте `YANDEX_GEOCODER_KEY` в окружении. Без ключа основная форма и расчёты работают, но поиск координат недоступен.

### Виртуальное окружение Python

Python не нужен для работы веб-приложения. Виртуальное окружение используется только как изолированное окружение для утилиты пересборки прайсов; сторонние Python-пакеты ей не нужны.

```powershell
py -3 -m venv .venv
.\.venv\Scripts\Activate.ps1
python --version
python .\build_prices.py
deactivate
```

Если PowerShell запрещает активацию окружения, запускайте Python напрямую:

```powershell
.\.venv\Scripts\python.exe .\build_prices.py
```

Утилита читает CSV из `All_Price_All_Marki/` и записывает `fixed/prices_data.js`. После изменения прайсов проверьте результат тестами и перезапустите/обновите приложение.

## Конфигурация

Список используемых имён переменных находится в `.env.example`:

- `CALC_PASSWORD`
- `YANDEX_GEOCODER_KEY`
- `AMO_INTEGRATION_ID`
- `AMO_SECRET_KEY`
- `AMO_REDIRECT_URI`
- `AMO_API_BASE`

В `.env.example` намеренно нет значений. PHP не загружает `.env` самостоятельно: задайте переменные окружения в профиле процесса, панели хостинга или конфигурации службы PHP. Не добавляйте реальные значения в Git.

`AMO_REDIRECT_URI` должен совпадать с URI, зарегистрированным в настройках интеграции amoCRM. `AMO_API_BASE` должен указывать на HTTPS API нужного аккаунта. После настройки интеграции откройте endpoint `amo/redirect.php` по предусмотренному amoCRM сценарию авторизации; OAuth-токены будут созданы в `fixed/amo/tokens.json`. Этот файл является секретным состоянием и исключён из Git.

## Автоматические проверки и главный сценарий

Из корня клона запустите синтаксическую проверку и тесты расчёта:

```powershell
node --check .\fixed\script.js
node --test .\tests\calculator.test.js
```

Для ручной проверки:

1. Запустите локальный сервер и войдите с паролем из `CALC_PASSWORD`.
2. Выберите прайс и марку, укажите площадь и толщину. Для проверки используйте ненулевую площадь и толщину не меньше 3 см.
3. Добавьте опцию, этаж или скидку и проверьте изменение итоговой стоимости.
4. Откройте «Формулу» и «Логист», проверьте детализацию.
5. Если серверная сессия настроена, проверьте загрузку и редактирование списков сотрудников.
6. Для проверки amoCRM настройте переменные окружения, OAuth и интеграцию; без них отправка в CRM не является успешным тестом.

## Публикация и обновление

Для production разместите **содержимое** `fixed/` в каталоге сайта, например `calc-2/`, сохранив подкаталог `amo/`. Не публикуйте корневые legacy-файлы репозитория вместо `fixed/`. Настройте PHP 8.0+, cURL, HTTPS и переменные окружения. Веб-сервер должен поддерживать правила Apache из `.htaccess`; если используется Nginx, настройте эквивалентный запрет прямого доступа к `staff_data.json`, `amo/tokens.json` и `amo/auth_log.txt`.

Для авторизации в amoCRM настройте интеграцию и URI перенаправления, затем пройдите OAuth. PHP-процессу нужны права чтения файлов приложения и записи в `fixed/` для общих списков, а также записи в `fixed/amo/` для OAuth-токенов и журнала авторизации. Ограничьте права на runtime-файлы и резервные копии.

Обновление из Git выполняйте в отдельной рабочей копии, проверив текущую версию и изменения до выкладки:

```powershell
git pull --ff-only
node --check .\fixed\script.js
node --test .\tests\calculator.test.js
```

Перед обновлением сохраните `staff_data.json`, `amo/tokens.json` и текущие настройки окружения. Не заменяйте runtime-файлы данными из репозитория, если они уже существуют. Сначала проверьте обновление на тестовом окружении, затем переносите изменённые файлы из `fixed/` на production.

## Резервное копирование и восстановление

Регулярно сохраняйте:

- `staff_data.json` — актуальные общие списки сотрудников;
- `amo/tokens.json` — OAuth-токены;
- настройки переменных окружения и конфигурацию веб-сервера;
- используемый `prices_data.js` и исходные CSV-прайсы.

Храните резервные копии вне web root с доступом только для ответственных администраторов. Не отправляйте копии runtime-файлов и секретов в Git или обычные публичные файловые хранилища. Для восстановления верните данные в те же каталоги, проверьте права PHP-процесса и повторите главный пользовательский сценарий.

## Известные ограничения

- Расчёт выполняется в браузере. CRM endpoint проверяет формат и диапазоны, но не пересчитывает цену независимо от клиента.
- Для геокодирования необходим действующий ключ Яндекса и доступ сервера к внешнему API.
- Для записи в amoCRM необходимы действующие OAuth-токены и разрешения интеграции.
- Вход использует общий пароль сотрудников; ограничение попыток привязано к IP и зависит от доступности временного каталога PHP.
- Локальный PHP-сервер не заменяет production-конфигурацию, HTTPS, мониторинг и резервное копирование.
- Тесты покрывают основные ветки расчёта, но не заменяют браузерные, интеграционные и нагрузочные проверки.

## Если что-то не работает

| Симптом | Что проверить |
|---|---|
| `php` не найден | Установлен ли PHP и добавлен ли каталог PHP в `PATH`; повторите `php --version`. |
| Вход не проходит | Задана ли `CALC_PASSWORD` именно для процесса PHP; не заблокирован ли IP после пяти неверных попыток на 15 минут. |
| Страница пустая или не стилизована | Откройте инструменты разработчика и проверьте загрузку `script.js`, `prices_data.js`, `style.css`, `jquery.min.js`; посмотрите журнал PHP. |
| Нет прайсов | Проверьте `fixed/prices_data.js`; выполните `python .\build_prices.py` из корня репозитория и повторите проверку. |
| Не загружаются общие списки | Проверьте PHP-сессию, CSRF-токен, права записи каталога `fixed/` и ошибки PHP. Для Apache убедитесь, что `.htaccess` разрешён. |
| Не работает адресный поиск | Проверьте `YANDEX_GEOCODER_KEY`, cURL и исходящий HTTPS-доступ с сервера. |
| Не работает отправка в amoCRM | Проверьте переменные интеграции, URL перенаправления, OAuth-файл токенов, cURL и журналы PHP. Не публикуйте токены в сообщениях об ошибках. |
| Изменения списков исчезают | Убедитесь, что PHP-процесс может записывать `staff_data.json`, и что файл входит в защищённые резервные копии. |

Серверные PHP-ошибки ищите в error log PHP/веб-сервера; при локальном запуске они выводятся в окно `php -S`. Не включайте подробный вывод ошибок для публичного production-сайта.
